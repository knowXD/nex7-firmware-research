## 第一层：设置/数据层（低风险，社区已验证）

| 项目 | 现状 | 改什么 |
|---|---|---|
| 语言解锁 | 菜单只有区域语言 | 0110_backup 里自带 ALLLANG 全语言 Backup.bin，刷入或改 language 字段 |
| 29:50 录像限制 | 欧版/部分区域限制 | Backup.bin 的 recLimit 字段（改成 13h01m） |
| PAL/NTSC 切换 | 区域锁定 | palNtscSelector 字段，顺带关掉开机 NTSC 提示 |
| NTSC 警告屏 | 每次开机提示 | 同上 |

这一层 OpenMemories 已经证明可行，风险接近零，恢复出厂可能会丢。

**复核**：❌ **"OpenMemories 证明可行"是错的**——OpenMemories 只面向有 Android 的机型（A7/NEX-6），
NEX-7 没有那一层。语言/时长是我们自己在 Backup.bin 上改的，与 OpenMemories 无关。
另：**具体字段偏移没有记进仓库**，用"对比出厂备份"也没能分离出来（见下）。

## 第二层：画质与色彩（中风险，改数据表）

| 项目 | 证据 | 收益 |
|---|---|---|
| JPEG 质量（Super Fine） | av-cam.bin 0x461092 是量化表，dgi_jpeg_qtable_calc_qscale 说明 qscale 是运行时算的 | 同尺寸画质明显提升，文件变大、连拍变浅 |
| 色度采样 4:2:0 → 4:2:2 | 编码器里有 subsample 参数 | 彩色细节改善 |
| 高 ISO 降噪/锐化 | High ISO NR 参数表 | 调低 NR 保住细节 |
| Creative Style 的 CCM/曲线 | 0x31e71c 有 14 个风格名（UI 只暴露 8 个） | 胶片模拟、A900 味 |
| 隐藏风格 | Nightview 等 | 可能解锁（要试） |
| AWB / 曝光偏移 | 参数表 | 改善偏绿/偏暗 |

**复核**：✅ JPEG 已实测完成（0x461092 量化表 + 0x6D032 qscale，属 `src/dgi_jpeg_qtable.c`）。
❌ **4:2:2 是无效条目**——实测发现 NEX-7 **本来就是 4:2:2**，无需改。
⚠️ 隐藏风格：uxc 私有格式，硬墙。

## 第三层：视频（中高风险）

| 项目 | 可行性 | 说明 |
|---|---|---|
| 码率 28 → 46Mbps+ | ★★★★ | 2012 年有人在 NEX-5N 上演示过 |
| Clean HDMI | ★★★ | codec key 偏方（0x01070087 → 0x0a），5N/6 验证过 |
| 音频 AGC / 风噪 / 电平 | ★★★ | 音频路径参数 |
| 斑马纹 | ★ | 固件里完全没有，要从零实现 |
| HDMI 输出格式 | ★★ | 目前只有 1080p/1080i/Auto |

**复核**：❌ **码率 ★★★★ 已被四次实测否定**（av-cam 字面量、libmpr 表、avcbits、bitrate2，
全部 100% 刷入且码率不变）。真正的旋钮在 av-cam 的 `SET_RC_WTPT` / `tVbrBufferValue`，未验证。
⚠️ Clean HDMI 的 "codec key 0x01070087" 没有在 NEX-7 上验证过，标注为 [推测]。
✅ 斑马纹"字符串 0 处"与本次扫描一致。

## 第四层：功能新增（高风险，要写代码）

| 项目 | 难度 | 价值 |
|---|---|---|
| 间隔拍摄/延时 | 中 | scenario.elf + OSAL 消息 |
| 焦点包围 | 中 | 驱动 AF 步进 + 连拍 |

**复核**：⚠️ "焦点包围能提高对焦速度"属于想当然，无证据。
⚠️ "连拍 buffer 加深"方向偏了——NEX-7 的瓶颈在写入，不在编码。

## 硬件/内核限制（别浪费时间）

4K / HEVC / ProRes / AVIF：没有编码器；Wi-Fi / 触摸 / 机身防抖：没有硬件；
exFAT：内核里字符串 0，也没有 FUSE，只能 FAT32，单文件 4GB 分卷；SDXC 高速：跑不满 UHS-I。

**复核**：✅ 已复核（exfat 0 次、fuse 1 次但无 /dev/fuse 模块）。
